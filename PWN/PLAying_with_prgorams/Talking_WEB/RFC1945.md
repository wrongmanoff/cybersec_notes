# rfc 1945 (REQUEST FOR COMMENT)

RFC 1945 defines the HTTP hyper text transfer protocol -- HTTP/1.0 is an application level protocl wiht the lighness and speed necessary for distributed collaborative, hypermedia information systems. A feature of HTTP is the typing of data represenation, allowing ssytems to be built independently of the data beign transferred. 

HTTP has been in use by the World_wide web global information initiative since 1990. 

## Simple HTTP request

```http
GET / HTTP/1.0
```

Request Line = **method** sp **Request-uri** sp **HTTP-VERSION** CRLF

sp = space , crlf = control line feed

### METHOD : 

1. GET : mean retrieve whatever information is identified by the request uri.

   Full HTTP Request : GET

   ```http
   GET /greet HTTP/1.0
   Host: hello.example.com
   ```

   Full Http response : GET

   ```http
   HTTP/1.0 200 OK
   Content-Type: text/html; charset=UTF-8
   Content-Type: 39
   
   <html><body>Hello, World!</body></html>
   ```

2. HEAD : it is identical to get except that the server must not return any entity-body in the response. this method can be used for obtaining metainformation about the resource identified by the request-uri without transferring the entity-body itself.  

   Full HTTP requeset: HEAD

   ```http
   HEAD /greet HTTP/1.0
   Host: hello.example.com
   ```

   Full HTTP response

   ```http
   HTTP/1.0 200 OK
   Content-Type: text/html; charset=UTF-8
   Content-Type: 39
   
   ```

   why we use head : we jst wanna check does this resource works, like how big is this video or file , like this works etc but doesn't requrie the actual content of the request-uri 

3. POST : is used to request that the destination server accept the entity enclosed in the request as a new subordinate of the resour idnetified byt the request-rui in the request-line . IT's basiclly pushing data to the server . we are posting the data to that remote sever

   Full HTTP request : POST

   ```http
   POST /greet HTTP/1.0
   Host: hello.example.com
   Content-Lenght: 11
   Content-Type: application/x-www-form-urlencoded
   
   name=Bhavesh
   ```

   FUll HTTP resoponse 

   ```http
   HTTP/1.0 200 OK
   Content-Lenght: 0
   ```

## Simple HTTP response

```http
HTTP/1.0 200 OK 
```

Status line = **HTTP**-**VERSOIN** SP **STATUS-CODE** SP **REASON-PHRASE** CRLF

### Status-code : 

- 1xx : **Information** - Not used, but reserved for future use
- 2xx : **Success** - The action was successfully received, understood and accepted
- 3xx : **Redirection** - Further action must be taken in order to complete the request
- 4xx : **Client ERror** - the request contains bad syntax or cannot be fullfilled 
- 5xx : **Server Errro** - The server failed to fulfill an apparently valid request

## Status Code Definitions: 

- 200 - OK
- 201 - Created
- 202 - Accepted
- 204 - No Content
- 301  - Moved permannetly 
- 302 - Moved Temporarily
- 304 - Not modified
- 400 - Bad request
- 401 - unauthorized
- 403 - forbidden
- 404 - Not Found
- 500 - INternal Server Error
- 501 - Not implemented
- 502 - Bad Gateway
- 503 - Service Unavailable
